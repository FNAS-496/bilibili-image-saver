### 「下载到最后一步提示链接已关闭」修好了喵 🐾

这个提示来自浏览器在**保存文件**这一步失败，不是下载本身失败。三个原因，全修了：

1. **`<a download>` 被加了 `rel="noopener"` / `target`** —— Chrome 会忽略 `download`，
   把 blob 地址当网页打开又立刻关掉，于是提示「链接已关闭」，文件根本存不下来。
   现在这两个属性彻底移除，并把节点挂到 `<html>`（SPA 框架只重渲染 `<body>`，挂 body 里会被连带清掉）。
2. **blob URL 被按固定时间回收** —— 原来 5 分钟就 `revokeObjectURL`，
   大文件遇上慢网速，下载还没完源就被删了。现在改成**页面卸载时统一回收**。
3. **ZIP 每包上限原来是 2GB（图片甚至没上限 = 4GB）** —— 整包字节要先在内存里拼成一个 Blob
   再交给浏览器，GB 级必然撑爆或中途失败。现在统一压到 **512MB** 自动分卷。

另外**不再强行走 `GM_download`**：它从 `blob:` 地址拿不到 MIME，Tampermonkey 会退化成按文本保存 ——
你下载的视频就变成 `xxx.mp4.txt`，双击打不开。上一版为了绕开「链接已关闭」用了它，结果换来这个新毛病。
现在 blob 一律走 `<a download>`，并且在创建 Blob 时就按扩展名补上正确的 MIME
（`video/mp4` / `audio/mp4` / `application/zip` / `image/jpeg` …）。

> 排查用：打开 B 站页面按 F12 看控制台，会打印
> `[check] 保存文件通道: <a download>（Blob 已带正确 MIME）`。

### 收藏夹视频下载修好了喵 🐾

之前收藏夹里点「视频下载」，列表只有寥寥几个（甚至一个都没有）—— 因为收藏夹页是**客户端渲染 + 虚拟滚动**，
`document` 里永远只有当前可见的十几条，脚本却只从 DOM 里抓。

这版改成**调收藏夹接口分页拉全**：

- 一千多个视频也能列全（一页 20 个，**边拉边显示**，不用干等）
- 为了不被风控：并发压到 2、每页间隔 350ms；万一还是被限流（HTTP 412），
  会明确告诉你「已加载 N 个 / 共 M 个，等几分钟重开面板」，已拿到的照样能下
- 失效稿件（`attr>0`）、番剧/课程等非视频（`type!==2`）自动跳过并计数
- 顺手支持了旧版入口 `www.bilibili.com/medialist/detail/ml<fid>`
- 修了一个隐藏坑：请求 JSON 接口时用 `Accept: text/html` 会被 B 站直接回 412（同一接口只换这个头就变 412）

另外收藏夹项**不再预取 cid 和大小** —— 一千个视频逐个请求 view/playurl 会慢到没法用，
改成勾选下载时按需获取。

### 怎么选喵

- **只想快点用上** → 便携版（`portable`），拖进浏览器就行，零安装喵；1080P / 4K 也能下，音画会在浏览器里自动合并成一个带声音的 mp4（不用装 ffmpeg）
- **要图片相册页 / 静默自动落盘 / 超大视频（合计 >512MB）** → 环境版或完整版
- **电脑上没装 Node** → 完整版（`full`），里面塞好了 Node 和 ffmpeg，双击 `一键启动.bat` 就能跑
- **想自己改功能** → 源码版（`source`），改 `src/bilibili-save.user.js` 后跑 `npm run build` 与 `npm run pack` 重新打包喵

### 安装喵

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)
2. 把包里的 `bilibili-save.user.js` 拖进浏览器窗口，点「安装」
3. 环境版 / 完整版再双击 `一键启动.bat` 启动本地服务（便携版不用）

每个包里都有一份**自己的**「使用说明.txt」（四个包各写各的，不共用模板喵——环境版讲自己装 Node、完整版讲已内置、源码版讲怎么改怎么打包），外加一份「文件说明.txt」把包内每个文件是干啥的、哪个能删，一条条列清楚。

> 所有 zip 里的中文文件名都按 UTF-8 并置了 EFS 标志位，解压不会乱码喵；
> 打包时会逐个条目回读校验 CRC，坏包发不出来。
