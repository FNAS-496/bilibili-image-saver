### 自动续载重做：接口分页为主，滚动只当兜底喵 🚀

上一版靠「滚页面」触发加载，问题是**把节奏和成功率都交给了页面**：
网慢会漏抓、内部滚动容器会失效、还完全控不住请求速度（之前就是这样把 IP 弄限流的）。
这版按「能拿到多少信息就用多好的办法」重做，三层逐级降级：

| 层级 | 方式 | 什么时候用 |
|---|---|---|
| ① **接口分页** | 直接调 `x/polymer/web-dynamic/v1/feed/space`，拿 `has_more` / `offset` 自己翻页 | 空间动态页（最优） |
| ② **页面自己的哨兵** | 滚到页面真正被 `IntersectionObserver` 观察的那个元素 / 点「加载更多」按钮 | 其它无限滚动页 |
| ③ **自塞隐形锚点 + 容器探测** | 找不到哨兵时，滚真正的滚动容器（自动识别 `overflow` 容器，不只是 `window`） | 最后兜底 |

**走接口带来的好处**：

- **能限速**：每页间隔 400ms、每次最多连拉 3 页，不再让页面自己乱发请求
- **能止血**：一旦 412（风控）立刻停手，不会越限越死
- **作者/文案是准的**：接口里每条动态自带 `module_author` / `module_dynamic.desc`，
  不用去 DOM 里猜，也不会因为虚拟滚动把图滚没了就认错人
- **图滚出屏幕也不怕**：URL → 作者映射缓存在内存里

**其它改进**：

- **不再死等固定毫秒**：原来是 `sleep(1400)` 猜时间，网慢就漏。现在用 `MutationObserver`
  等页面**真的长出新内容**，快网立刻返回、慢网也不会漏
- **有刹车了**：审查面板左栏新增「♾ 自动续载中 · 已加载 N 张」+「⏸ 暂停自动续载」，
  暂停后不再续载（已加载的图照样能审），随时可以继续
- **有上限了**：总量到 3000 张自动停，不会一路滚到天亮
- 修了个小不一致：底部「下载进度」的分母以前固定在开面板那一刻，续载后不更新

### 修一个「自动续载静默失效」的 bug 喵 🐛

上一版（v0.11.3）加的自动续载里，那个「隐形锚点」用了 `position:fixed`。
看起来没问题，但**固定定位元素的包含块是视口，不是滚动容器** ——
对它调 `scrollIntoView()` 页面根本不会滚动。实测证据：

```
修复前：scrollY 0 → 0，图片 8 → 8 张   ❌
修复后：scrollY 0 → 4849，图片 8 → 12 张 ✅
```

也就是说，**在没有「加载更多」按钮的纯无限滚动页面上，自动续载等于没生效**
（我当时的测试页恰好都有按钮，走的是「点按钮」分支，把这个坑盖住了）。

现在：锚点改成**静态定位**（真在文档流末尾、1×1、透明、鼠标可穿透），
外加一条兜底 —— 万一 `scrollIntoView` 没滚动（页面用某个 `overflow` 容器滚动），
就直接 `window.scrollTo(0, 文档总高度)`。

测试也补了对应守卫：
- 锚点出现 `position: fixed|absolute` 直接失败
- 必须有「滚到文档底部」的兜底
- 端到端在「完全没有按钮」的页面上验证：页面真的滚了、新图真的出来了、审查面板分母从 8 涨到 16

### 审查模式可以「一直有图」了喵 ♾️

B 站的动态列表和新版收藏夹都是**无限滚动**：不滚到底，新内容永远不出现，
所以审查模式审到第 20 张就断了 —— 你还得自己滚一下页面再重新提取，很烦。

这版给你两件东西：

**① 自动续载（一直有图）**
- 脚本会在页面最底端放一个 **1×1 的隐形锚点**（透明、不挡鼠标、不在正常布局里占位）
- 需要加载新内容时，把它滚进视口 —— B 站的无限滚动就会去拉下一页；
  如果页面上有「加载更多 / 下一页」按钮，则**优先点按钮**（分页式页面只能这样）
- 审查模式翻到最后一张会**自动接着加载**，进度从「1 / 20」变成「1 / 40」，
  状态栏会显示「↻ 还有更多」；真的到底了就不显示，不再反复尝试
- 开关在「🖼️ 图片下载」盒子里，默认关（不想让脚本动页面就别开）

**② 每次最多下载 N 张**
- 填 0 = 不限；填 30 就每次只处理 30 张
- 自动下载模式：只取前 N 张，并提示「本次只处理前 N 张」
- 审查模式：「全部下载」按钮变成「全部下载（最多 N 张）」，下完这一批**不关面板**，
  提示「还有 37 张没下，再点一次继续」；配上自动续载就是
  **下 N 张 → 翻到底自动加载下一批 → 再下 N 张**，挂机也能慢慢收干

> 为什么不直接「自动跳转到下一页 URL」：整页跳转会丢掉已提取的图片队列和审查进度。
> 滚动/点按钮是在同一页里增量加载，队列和进度都能保住。

### 大视频（4K / 几个 GB）现在真的能下完了喵 🐘

之前有个硬伤：下载超时是「**总共只准下 10 分钟**」，一到点就掐断。
一个 4K 视频几个 GB，慢网速下正常就要下半小时以上 —— 于是越大的视频越必然失败，
还容易在「下载到最后一步」时挂掉。

这版全改了：

- **超时改成「多久没收到新数据才放弃」**（默认 120 秒无数据）。只要还在往下传，
  下多久都行；真的卡死了才断开，并自动换一条 CDN 地址重试
- **服务端全程流式写盘**，视频不进内存。实测：文件从 50MB 涨到 200MB，
  内存峰值只从 69MB → 72MB（整块读进内存的对照组是 206MB）
- **失败不留半成品**：以前断了会留一个坏文件，查重把它当成「已下好」，
  之后怎么点重下都被跳过。现在断了立刻删掉，半成品一定会在句柄关闭后再删（Windows 上才删得掉）
- **启动时清理上次异常退出的垃圾**：下载中断留下的 `.tmp_` 文件可能有 GB 级，
  现在服务启动会把 24 小时前的残留删掉并报告释放了多少空间
- **ffmpeg 合并音画的超时从 10 分钟放宽到 30 分钟**（4K 大文件在慢盘上合并确实要久）
- **便携版**：选了授权目录时单文件视频是**边下边写**（不占内存）；
  DASH 音视频合并上限 512MB，超了会自动改成「音画分开存」并明确告诉你，不会白下
- **下载目录页看大视频**支持拖进度条（`/video/<名字>` 支持 Range）

### 「下载到最后一步提示链接已关闭」修好了喵 🐾

这个提示来自浏览器在**保存文件**这一步失败，不是下载本身失败。三个原因，全修了：

1. **`<a download>` 被加了 `rel="noopener"` / `target`** —— Chrome 会忽略 `download`，
   把 blob 地址当网页打开又立刻关掉，于是提示「链接已关闭」，文件根本存不下来。
   现在这两个属性彻底移除，并把节点挂到 `<html>`（SPA 框架只重渲染 `<body>`，挂 body 里会被连带清掉）。
2. **blob URL 被按固定时间回收** —— 原来 5 分钟就 `revokeObjectURL`，
   大文件遇上慢网速，下载还没完源就被删了。现在改成**页面卸载时统一回收**。
3. **ZIP 每包上限原来是 2GB（图片甚至没上限 = 4GB）** —— 整包字节要先在内存里拼成一个 Blob
   再交给浏览器，GB 级必然撑爆或中途失败。现在统一压到 **512MB** 自动分卷。

另外**不再强行走 `GM_download`**：它从 `blob:` 地址拿不到 MIME，Tampermonkey 会退化成按文本保存 ——
你下载的视频就变成 `xxx.mp4.txt`，双击打不开。上一版为了绕开「链接已关闭」用了它，结果换来这个新毛病。
现在 blob 一律走 `<a download>`，并且在创建 Blob 时就按扩展名补上正确的 MIME
（`video/mp4` / `audio/mp4` / `application/zip` / `image/jpeg` …）。

> 排查用：打开 B 站页面按 F12 看控制台，会打印
> `[check] 保存文件通道: <a download>（Blob 已带正确 MIME）`。

- 失效稿件（`attr>0`）、番剧/课程等非视频（`type!==2`）自动跳过并计数
- 顺手支持了旧版入口 `www.bilibili.com/medialist/detail/ml<fid>`
- 修了一个隐藏坑：请求 JSON 接口时用 `Accept: text/html` 会被 B 站直接回 412（同一接口只换这个头就变 412）

另外收藏夹项**不再预取 cid 和大小** —— 一千个视频逐个请求 view/playurl 会慢到没法用，
改成勾选下载时按需获取。

### 怎么选喵

- **只想快点用上** → 便携版（`portable`），拖进浏览器就行，零安装喵；1080P / 4K 也能下，音画会在浏览器里自动合并成一个带声音的 mp4（不用装 ffmpeg）
- **要图片相册页 / 静默自动落盘 / 超大视频（合计 >512MB）** → 环境版或完整版
- **电脑上没装 Node** → 完整版（`full`），里面塞好了 Node 和 ffmpeg，双击 `一键启动.bat` 就能跑
- **想自己改功能** → 源码版（`source`），改 `src/bilibili-save.user.js` 后跑 `npm run build` 与 `npm run pack` 重新打包喵

### 安装喵

1. 浏览器装 [Tampermonkey](https://www.tampermonkey.net/)
2. 把包里的 `bilibili-save.user.js` 拖进浏览器窗口，点「安装」
3. 环境版 / 完整版再双击 `一键启动.bat` 启动本地服务（便携版不用）

每个包里都有一份**自己的**「使用说明.txt」（四个包各写各的，不共用模板喵——环境版讲自己装 Node、完整版讲已内置、源码版讲怎么改怎么打包），外加一份「文件说明.txt」把包内每个文件是干啥的、哪个能删，一条条列清楚。

> 所有 zip 里的中文文件名都按 UTF-8 并置了 EFS 标志位，解压不会乱码喵；
> 打包时会逐个条目回读校验 CRC，坏包发不出来。
